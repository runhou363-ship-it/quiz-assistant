# 答题学习助手（学习辅助版）

一个浏览器插件 + 本地后端，用来**辅助你学习刷题**：抓取题目 → 搜索并推理 → 把**答案和解析**整理出来发给你。**全程不替你选答案**，只做「找答案 + 翻页 + 汇总」。支持从网页链接一键启动、批量处理章节。

> ⚠️ 用途边界：仅用于个人学习、自测、练习。请勿用于正式考试、职业资格测评或任何违反平台规则的考核场景。

## 架构

```
浏览器插件 (MV3)                      本地后端 (Flask)
┌──────────────┐   题目+选项(JSON)    ┌────────────────────┐
│ popup.html   │ ──── solve ───────▶ │ /solve             │
│  设置后端地址 │                      │  1. 网页搜索取线索  │
│ inject.js    │ ◀── 答案+解析 ────── │  2. 多视角并行推理  │
│  抓取题目UI  │                      │  3. 分歧才取证/复核 │
│  展示结果    │                      │  4. 返回JSON        │
└──────────────┘                     依赖 OPENAI_API_KEY
```

- **popup.js**：设置后端地址；提供「统计本页章节数」、「链接入口」（粘贴网页链接 → 后台自动打开并解答）、「合并已保存的报告」、「当前页面启动」。
- **inject.js**：在页面内生成浮动面板，自动抓取题干与选项（也允许手动修正），调用后端，展示推荐选项与解析（**不直接点击选项**）；支持「自动模式」逐题找答案并翻页。
- **background.js**：转发 `/solve` 请求；`count_chapters` 在当前页做 SPA 友好的章节统计（展开 + 滚动 + 轮询 + 文本识别，**只读**）；`open_and_run` 负责打开链接、注入脚本、自动启动，并用同一套扫描逻辑找「章节/课时」链接逐页处理。
- **server/app.py**：多视角并行推理 + 答案自洽校验 + 分歧裁决（v0.8.0 起常规题不联网，仅分歧时按需搜索取证），返回 `answer_index`/`explanation`/`confidence`/`timing`；另有同题答案缓存、字体解码、`/report`、`/combine`。

## 运行步骤

1. 启动后端：
   ```bash
   cd server
   pip install -r requirements.txt
   copy .env.example .env          # Windows；然后编辑 .env 填 OPENAI_API_KEY=你的key
   python app.py
   ```
   也可以直接双击项目根目录的 `start-server.bat`（会 cd 到 server 并运行 `python app.py`）。
   默认监听 `http://127.0.0.1:8787`。验证：`curl http://127.0.0.1:8787/status` 会返回是否已读到 key。
   > 国内网络直连 `api.openai.com` 通常不通。若报 `ProxyError / Connection` 之类，请在 `.env` 里加
   > `OPENAI_BASE_URL=你的可用中转地址`（任何 OpenAI 兼容服务都可以，如 DeepSeek、通义、自建代理），
   > 并把 `OPENAI_MODEL` 改成该服务支持的模型名。

2. 加载插件：
   - 浏览器打开 `chrome://extensions`（或 Edge 的 `edge://extensions`）。
   - 开启「开发者模式」。
   - 点击「加载已解压的扩展程序」，选择 `extension/` 目录。

3. 使用（三种入口）：
   - **自动看视频（v0.9.10 新增）**：在**已登录**的课程目录页点插件图标 → ① 区「开始自动看视频」。
     只认左侧目录里的「视频」标记并点开，等真实播放器播完再滚动找下一个；「作业 / 测验」一律跳过，题目由你自己手动点。
     **不提交、不答题、不替你选，也不需要启动后端或消耗 API Key。**
   - **链接入口（推荐）**：点击插件图标，在「题目网页链接」粘贴你的课程/答题页 URL，
     勾选「连同本页的章节/课时链接一起处理」可批量跑多个章节，点「打开并自动解答」。
     插件会逐个页面自动找答案并翻页（不替你选），每页报告存入后端 `reports/`。
     全部跑完后点「合并已保存的报告」得到一份总表并下载。
   - **手动入口**：在当前答题页点「在当前页面启动辅助」，面板出现后手动操作或开启「自动模式」。
   - 无论哪种入口，选项都**由你自行决定点击**，工具只负责整理与翻页。

## 统计章节数（SPA 友好，只读）

> 注：v0.9.10 起弹窗 ① 区已换成「自动看视频」，下面这套章节扫描能力仍保留在 `background.js`，供 ② 区「连同章节链接一起处理」复用。

很多课程平台（雨课堂、学习通等）是 SPA，章节在滚动或展开后才渲染，普通「抓 `<a>` 链接」会漏。这里的做法是四步：

1. **展开**：点一遍页面上文本为「展开 / 展开全部 / 显示更多 / 加载更多 / 更多」的短按钮（最多 20 个，只认短文本，避免误点）。
2. **滚动**：把窗口和所有内部滚动容器分步滚到底，触发懒加载，直到高度不再增长。
3. **轮询**：多轮（约每 450ms 一次，连续 2 轮无新增即停）收集「像章节」的节点，并跳过容器节点（内部还有 2 个以上章节命中的大盒子）。
4. **识别**：支持 `第X章 / 第X节 / 第X讲 / 第X单元 / 第X部分 / 第X周`、`1`、`1.1`、`1.1.1`、`Chapter N` 等编号；中文数字（第一章）会归一化成阿拉伯数字，便于和 `1.1` 归入同一顶层章节。

输出：章节条目总数、顶层章节数、按层级分布、任务点约数（视频/课件/习题/测验/作业/讨论/文档/音频/考试/PPT/PDF…）、以及可核对的清单。

**会误判的情况**：页面同时用「1.1」当题号又当章节号、隐藏模板节点、目录里混进非章节项。所以结果设计成「可核对清单」而不是一个绝对值；清单能直接复制贴出来人工确认。

**注意**：只统计当前标签页的内容。像雨课堂的「未完成 / 已完成」两个标签，需要切过去分别统计一次再相加。

## 关键设计点

- **人始终在回路里**：工具只展示结论与理由，点击动作由你完成，既保留学习价值，也避免被判定为自动化代答。
- **可修正的识别**：不同答题平台 DOM 差异大，自动抓取可能不准，所以题干和选项都可编辑。
- **本地优先**：题目只发到你自己运行的本地后端，不经过第三方。

## 已知限制 / 可增强

- 自动抓取依赖常见 DOM 结构；非常规布局需手动填写，或后续接入「截图 + OCR」识别图片题。
- 中文题干的网页搜索在国内网络下经常不可用（DDG 超时、Bing 返回字典词条），v0.8.0 起常规题不联网，只在分歧时按需取证并自动降级；准确率主要靠结构化推理、答案自洽校验与裁决复核。可用 `QA_SEARCH=on` 强制每题搜索。
- 可增强：接入可用的中文搜索 API、多模型回退、错题本、按站点定制选择器。

## 两种模式

- **手动模式**：点「查找答案」看推荐答案+解析，自己点选项、自己翻页。
- **自动模式（不替你选）**：勾选面板里的「自动模式：自动找答案并翻页（不替你选）」后，工具会——
  1. 自动抓取当前题 → 找答案 → 记录（题干/选项/推荐答案/解析）；
  2. 停留你设定的秒数（默认 1 秒，可调 0–15 秒）后，**自动点「下一题」翻页**（注意：全程**不点击任何选项**）；
  3. 循环直到找不到「下一题」按钮（视为结尾），自动在面板里生成汇总。
- **结束汇总**：无论哪种模式，点「查看汇总」都会在面板窗口里显示汇总（按题目顺序，含推荐答案、你的选择、解析），
  **不再下载文件**；需要文本可点「复制汇总文本」。副本会静默 POST 到后端 `POST /report` 保存到 `server/reports/`，
  供 popup 的「合并已保存的报告」使用；合并结果同样在弹窗内显示、不下载。

> 说明：自动模式**只做「找答案 + 翻页」**，绝不替你选择正确选项。翻页是否被允许取决于平台（部分平台要求先选一个选项才能继续，此时自动模式会停下提示你）。最终作答由你自行决定。

## 验证层（提高正确率 / 处理不确定）

后端 `/solve` 的默认流程（v0.8.0，实测单题 3~4.5 秒，旧版约 11 秒）：

1. **多视角并行采样**：同一题并行调用模型 `QA_SAMPLES` 次（默认 3），温度 0~0.5，每次换一种思考视角（常规 / 圈否定词 / 反证 / 教材表述 / 概念核对），要求逐项分析每个选项；**单选与多选统一输出答案集合** `answer_indices` / `answer_texts`。
2. **答案自洽校验**：模型常出现「解析写选 4、`answer_index` 却写 3」。Python 以 `answer_text` 与解析里「故选/答案为」的结论为准自动修正序号（`self_fixed`）。
3. **多数投票 + 置信度**：全票一致 → `high`；过半 → `medium`；平票/全分歧 → `low`；全部答不出 → `none`。不再要求「必须有搜索证据」才给 high。
4. **按需取证 + 裁决复核**：只有出现分歧或不确定时才联网搜索（双引擎并行、4 秒超时、30 分钟缓存、相关性过滤），从题库片段抽「正确答案: C」作为独立信号，并追加一次「重新审题裁决」采样；裁决可推翻多数票，原始分歧仍保留在 `disputed` 供报告展示。
5. **搜索自动降级**：连续两次拿不到相关线索就跳过后续联网（`/status` 的 `search_degraded` 可见），不反复白等。
6. **同题缓存**：按题干+选项+模型缓存答案，`cached=true` 时秒回；`QA_CACHE=0` 或请求带 `nocache` 可绕过。
7. **报告按题目顺序**：汇总正文严格按第 1 题→第 N 题排列，置信度只写在每题里（开头给概览统计），不再按置信度分栏打乱顺序；无答案时 `answer_index=null`，不硬编。

> 实测：雨课堂真题「以下哪项不是自然辩证法的特点」，旧版推荐 D 哲理性（错）且标争议；v0.8.0 三次一致给出 C 复杂性，与教材、雨课堂题库答案一致，高置信。
> 仍**不保证 100% 正确**：主观题、计算题、题目抽取错误都会拉低准确率。可用 `QA_SAMPLES=5` 或换更强的 `OPENAI_MODEL`。

## 抓取适配与「诊断结构」

不同平台 DOM 差异很大，插件（v0.5.0）会先把**主文档 + shadow root + 同源 iframe** 一起纳入搜索，再依次尝试四种选项识别策略：

1. **单/复选框**：找 `input[type=radio|checkbox]` 的 label 文本（**已排除插件自己的面板**，否则会把面板里的勾选框当成选项）。
2. **字母分组**：同一父级下出现连续的 `A / B / C / D`（允许 `A.`、`A、`、`A)`、`A：`、`A．`，也允许「圆圈字母 + 文字」这种字母后无分隔符的结构），取最长的一组。
3. **字母单独成块**：字母在独立圆圈里、文字是兄弟节点时，按兄弟顺序配对。
4. **重复同级块**：字母用图标或 CSS 渲染、文本里根本没有字母时，把「同一容器下 3–10 个等长短文本块」当选项（要求上下文里出现 `单选题/选择题/（ ）`，并排除纯数字的题号导航）。

题干不再靠「取最长文本」，而是**用第一个选项文字把容器文本切开**，前半段就是题干，再清掉 `1.单选题（1分）` 前缀与尾部残留字母；兜底只认含 `（ ）`、`？`、`下列/以下/哪项` 的短句，并排除 `知识点/目录/提交` 这类导航词（v0.4.0 曾把侧边栏的「知识点」当题干，已修）。

翻页同样有四级策略：`下一题` 文案 → `aria-label/class` 含 next → **题号导航（找当前高亮的题号，点下一个）** → 箭头字符 `› > →`。**不再把「提交」当作下一题**，避免误交卷；找不到就按结尾处理并导出汇总。

当某页抓不到时，面板里点「**诊断结构**」：它会把页面快照（可搜索根数量、iframe/shadow 统计、按钮清单、字母候选含 HTML、题号导航、正文前 4000 字、题型标签的父级 HTML）POST 到 `POST /debug`，存成 `server/debug/debug-<时间戳>.json`，据此适配选择器。若 `meta.refusedFrames > 0`，说明习题区在**跨域 iframe** 里，当前主文档看不到，需要改成多 frame 注入。

离线测试：`node tests/extract.test.js`（5 组用例：圆圈字母、`A、` 结构、不抓自己面板、侧边栏干扰+4 子元素、字母为图标兜底）。

## 加密字体解码（雨课堂 / 学堂在线）

雨课堂把题目、选项的汉字用 `class="xuetangx-com-encrypted-font"` 的**动态字体**重新编码：页面上显示「综合性」，DOM 里存的是「导责色」。所以 `innerText` 抓到的永远是错字，跟选择器无关。

处理链路（v0.7.0）：

1. 插件找字体走**三条路**（任何一条命中就够）：
   - 同源样式表里的 `@font-face`，族名/URL 含 `crypt|exam` 的优先；
   - 跨域样式表读不到 `cssRules`（会抛 SecurityError），改由后台 `fetch_text` 把 CSS 文本抓回来再解析；
   - `performance.getEntriesByType("resource")` 里筛字体资源（字体一定被浏览器下载过，跨域也能拿到 URL），以及 `link[as=font]`。
   候选按名字打分：`exam-data-decrypt-font` 这类 100 分，MathJax/KaTeX 公式字体 −60 分直接排除；抓回来的字节先验魔数（`wOF2/wOFF/OTTO/true/ttcf`），不是真字体就跳过。`blob:` 地址后台取不到，回退到页面内 `fetch`。
2. 调 `/solve` 时把 `font_b64` 一起发过去。
3. 后端 `fontdec.py` 解码（判字体 → 逐字比对）：
   - 把每个混淆字形渲染成多尺寸位图（64/96/112），裁到墨迹包围盒后缩放到 56×56，融合投票；
   - **关键：参考字体必须与加密字体同源**。读字体 `name` 表可知雨课堂用的是 `Source Han Sans SC VF`（思源黑体简体 · 可变字体，ExtraLight 字重）。早期版本误用微软雅黑比对，平均命中分只有 ~1.0，「学→字」「统→绞」「机→村」等形近字反复认错（正确字甚至排不进 top5）；改用 `server/fonts/NotoSansSC-VF.ttf`（或系统自带同源字体）后拟合 **1.93~1.98**，`unresolved` / `low_conf` 清零，5 份历史字体全部零错字。
   - 仍会遍历 msyh / simsun / simhei / simkai 作为回退（合成宋体字体仍能正确选到 simsun 2.0），拟合 ≥1.60 即早停；
   - 单字分数 < 0.75、或最好的参考字体平均分 < 0.85（说明没有相近字体）时，**保留原字不硬猜**，并在 `unresolved`/`low_conf` 里列出来。
4. 解出的真字回写到插件面板，题目/选项/报告里都是真字。
5. **形近字兜底校对**：雨课堂每换一页会换一份字体，个别字用字形比对救不回来（正确字甚至排不进 top5）。`/solve` 的 3 次采样会顺带把明显不通顺的词改回正字（如「村械唯物主义」→「机械唯物主义」、「钬积论」→「认识论」），**至少 2 次采样一致才采纳**，并把纠正后的题干/选项写回面板与汇总报告；DOM 密文不动，翻页判断不受影响。复用已有调用，不额外花钱。

> 为什么不是「每个字跨字体取最高分」：2026-11 用真实雨课堂字体（`exam_font_9e8180…ttf`，20 字人工标注）实测——微软雅黑 20/20（最低 0.842），黑体 14/20，宋体 8/20，楷体 3/20。逐字取最高会把别的字体里"看起来更像"的错字挑出来（特→恃、是→疙、合→台）。

参考字体的 56×56 位图矩阵缓存到 `server/cache/ref-*.npz`（每个字体每个尺寸一份），首次构建约 4–5 秒/份，之后加载 <0.3 秒；`python app.py` 启动时会后台预热（含 sourcehan 的三个融合尺寸），用户首次点「查找答案」不必等。判定为同一字体的加密文本，二次解码走按字体 md5 落盘的映射缓存（约 5ms）。

字体文件 `server/fonts/NotoSansSC-VF.ttf` 来自系统自带的 Noto Sans SC（SIL OFL 1.1，允许随软件分发），详见 `server/fonts/README.txt`。程序优先用项目内副本，其次找系统字体目录；都没有才回退到雅黑（准确率会下降）。`/status` 的 `font_refs` 里有 `sourcehan` 即表示已启用。

> `POST /debug` 现在会**自动自检解码**：收到的 `font_b64` 另存为 `debug-<时间戳>.font`，立刻用 `fontdec` 解一遍题干/选项/加密片段，结果写进 json 的 `selfDecode`（含 `avg_score`、`ref`）。所以点一次「诊断结构」就能判断字体取没取到、解得对不对。

单独验证接口：`POST /decode {font_b64, texts}`。

## 后端接口

- `GET  /health`  健康检查，返回 `ok`
- `GET  /status`  返回是否已读到 API Key（打码）、模型、采样数、`engine`、`search_mode`/`search_degraded`/`verdict`/`answer_cache`、字体解码器状态，用于排查配置

- `POST /debug`   接收插件采集的页面结构快照，写入 `server/debug/debug-<时间戳>.json`；带 `font_b64` 时另存 `.font` 并写入 `selfDecode`
- `POST /combine` 合并 `server/reports/` 下所有 `report-*.md` 为一份总表，返回 `{ok, count, markdown}` 并写出 `combined-<时间戳>.md` / `.json`

## 自动续跑修复（v0.9.5）

现象：新开一个页面（或重新注入面板）后，点「重新抓取」能识别出题目，但不会自动点「下一题」，自动流程像是停住了。

根因与修复：

| # | 根因 | 修复 |
| --- | --- | --- |
| 1 | 「重新抓取」只调用 `load()` 刷新面板，从不触发 `autoStep`/`advance`，自动流程就算开着也被晾在那里 | `load(resume)` 增加续跑参数，抓完题若自动模式还开着，立刻 `startAuto()` 接着跑 |
| 2 | `runSolve()` 抓不到选项时直接把 `autoMode/autoRunning` 关掉。新开页面题目还没渲染完就会抓空 → 自动模式被静默关闭，用户看到的就是「识别完不翻页」 | 改为记录失败原因并不关自动模式；`autoStep` 对「抓空」单独走 5 次短等待重试（0.7s→2.7s），只有连续抓空才暂停且保留勾选 |
| 3 | 勾选状态只存在 `qaAutoState.active` 里，而面板每次注入都是新实例，`restoreAuto()` 要求 `active=true` 才恢复 → 新标签页永远恢复不了自动模式 | 新增独立的「自动模式意图」`qaAutoEnabled`，勾选/取消即持久化；新面板启动后按意图自动开跑 |
| 4 | 字体文件取空时 `fontPromise` 被永久缓存成失败结果，这个面板之后再也拿不到字体，只能看假字 | 失败不缓存，并清掉字体线索缓存，下次重试重新扫描；`load()` 额外在 1.5s 后补一次解码 |
| 5 | 多条自动流程链可能并存（勾选 + 恢复 + 翻页回调各起一条），互相抢题、重复点「下一题」 | 引入 `runToken`，任何一次启动都让旧链失效；`autoStep/advance/waitNext` 全部校验 token |
| 6 | 平台 SPA 自己换题（手动点下一题、同标签换作业）时面板停在旧题 | 新增去抖的 `MutationObserver`：自动流程在跑时不动它；停下来且换了新题就刷新面板并按需续跑；已整理过的题不会重复作答 |

翻页判定也顺手加固：原来只比题干文本，题干抓不出来会被误判成「翻页没生效」；现在用「题干 + 选项」整体指纹比对，并把轮询放宽到 12×350ms。

## 「重新抓取」= 从当前题重新汇总（v0.9.8）

原来「重新抓取」只刷新面板、续跑自动流程，汇总仍保留着之前所有题；跑到一半想以当前题为一个新的起点时没有入口。

现在的语义：

| 当前题的状态 | 点「重新抓取」的结果 |
| --- | --- |
| 已整理过（汇总里有这道题） | 之前的汇总整份清空，当前题重新作答，汇总从这道题开始重新累加 |
| 还没整理过（断线续跑常见） | 保留之前的进度，从本题接着记；状态栏提示「8 秒内再点一次」可清空重来 |
| 汇总本来就是空的 | 仅刷新识别结果，不做任何清空 |

实现要点：

- `load(resume, fromButton)` 多一个「来自按钮」的标志，`resetSummary()` 负责清空 `sessionLog` 并隐藏旧报告、重置 `currentEntry`，随后 `saveAutoState()` 落盘，刷新页面也不会把旧汇总带回来。
- 清空前把整份记录存进 `undoSnapshot`，面板第二行出现「**撤销清空**」，点一下即还原；等新汇总写到第 2 题快照才作废（自动模式清空后会立刻重算当前题，第 1 题期间仍可撤销）。
- 撤销时若自动流程正在跑，会先 `pauseAuto()` 停下（勾选框一并取消），否则新算出来的题会跟在还原的旧汇总后面。
- 双击防误触：两次点击间隔 <0.4 秒视为同一个动作，不会触发清空；「再点一次确认」的有效窗口是 8 秒。
- 并发保护：`logEpoch` 汇总版本号在清空/撤销时 +1；正在飞的作答请求回来发现版本不对，就不再写进汇总，避免出现「撤销后又冒出一条重复记录」。

回归用例 `tests/autorun.e2e.mjs` 增加到 10 个场景（H：回到已做过的题后清空并重跑；I：撤销还原；J：未做过的题上第一次保留、第二次清空），全部通过。

## 关于「接入夸克搜题插件」（v0.9.9）

查证结论：**不能程序化接入**。原因不是意愿，而是没有可接的入口。

| 障碍 | 说明 |
| --- | --- |
| 没有公开 API | 夸克拍照搜题 / 截屏搜题是面向人的产品功能，需登录态与风控签名；第三方资料也标注夸克 AI「无公开 API」 |
| 有开放平台，但能力不对 | `scan.quark.cn/business` 公开的是通用文字识别、手写识别、表格还原、**题目识别提取**（把图片里的题 OCR 成文字），需开发者 Key，**没有「题干文本 → 标准答案」的题库接口** |
| 形态绕远路 | 夸克是「截图 → OCR → 搜题」；本工具已经是「DOM 文本 → 字形反查 → 干净真字 → 模型」。再渲染成图片去搜，等于把已修复的形近字问题重新引入 |
| 扩展互相隔离 | MV3 content script 调不到另一个扩展的弹窗/内部接口；只能做 CDP / UI 自动化，是另一套架构，且对方一改版即失效，还涉及协议与风控 |

所以改为提供一个**合规、零成本、不会失效**的人工核对入口：

- 面板新增「**夸克核对（复制本题）**」：把面板里的题干 + 带 A/B/C 前缀的选项复制到剪贴板，同时打开 `https://www.quark.cn/s?q=<精简题干>`（实测会带查询词打开夸克 AI 搜索页）。用户可直接在搜索框粘贴完整题目核对。
- 复制用 `navigator.clipboard`，失败时降级 `textarea + execCommand('copy')`；「复制汇总文本」也统一改用这套带降级的逻辑。
- 只在用户手动点击时动作：**不发任何自动请求、不写 `sessionLog`、不碰 `runToken`**，自动翻页流程完全不受影响；弹窗被拦截时状态栏会提示已复制、请自行打开夸克。
- 低置信 / 有分歧 / 未找到答案时，结果区会提示「点夸克核对再查一遍」。

回归 `tests/autorun.e2e.mjs` 增至 11 个场景全过（K：验证复制提示、打开地址带题干、题号/计数/自动模式均不变）。


## 自动看视频（v0.9.10）

用户诉求：左侧目录里混着「视频」和「作业」两类任务点，希望**视频自动点开看、看完自动滚动找下一个视频**，作业全部留给自己手动点。

实现（`extension/video-brush.js`，独立 content script，由 popup 注入顶层文档）：

| 环节 | 做法 |
| --- | --- |
| 识别 | 跨同源 iframe 收集所有文档，找文本恰好为「视频」的短标签元素；向上找所属条目行；其它类型（作业/测验/考试/讨论/图文…）记为 `skip`，**从不进入点击队列** |
| 去重 | 优先用条目行上的 `data-node-id` 等；只认「行级元素」的普通 `id`，避免所有条目撞上同一个 `<ul id>`；再兜底用去状态词后的标题文本 |
| 点开 | 依次尝试「视频」标签自身的可点击祖先 → 标签 → 行内链接/按钮 → 整行；每次点击后对比 URL / 播放器签名 / 完成标记，判断是不是真的点开了，没反应就换下一个候选 |
| 判定看完 | 跨文档找 `<video>`，`ended` 或 `duration - currentTime <= 1.5s` 视为播完；播放器消失或平台把条目标成「已完成」也算（至少等 3 秒防止点开瞬间误判）；单集超时默认 20 分钟则跳过 |
| 找下一个 | 看完后重新扫描目录，跳过已完成/已处理的；找不到就把左侧可滚动容器往下滚，触发懒加载后再扫，最多 3 轮 |
| 可控 | 页面顶部浮窗显示阶段/已看数/当前视频/进度，随时暂停或停止；「停止」用 `interruptibleSleep` 立刻打断间隔等待 |

安全边界：

- 点击目标会过滤「提交 / 交卷 / 确定 / 下一题 / 答案」以及所有短文本里带「作业 / 测验 / 考试」的元素。
- 不调用任何平台接口、不伪造学习时长；默认 1 倍速且不改动播放器，用户可显式选 1.5x / 2x。
- 两次点击至少间隔 1.2 秒；页面刷新后**不会**自动恢复运行（状态会被写成 stopped），必须重新点「开始」。
- 弹窗 ① 区提供「诊断目录」，先列出识别到的标记再决定是否开始，便于发现目录结构不兼容。

验证：`tests/videobrush.e2e.mjs` + `tests/mock-course.html`（无头 Chrome + CDP）6/6 通过：诊断能区分视频/作业、作业一次都没被点、5 个视频按序看完不重复、滚动懒加载后继续找、进度与浮窗、停止立刻生效。原有 `tests/autorun.e2e.mjs` 11/11 仍全过。

## 流畅度与点击可靠性（v0.9.11）

反馈：目录一多就卡顿，偶尔点了没反应。

**卡顿**：最大的开销是 `collectItems()` 对 `querySelectorAll` 命中的**每个元素**读 `innerText`——这會强制浏览器重排，几百条目的目录里逐元素读就是明显卡顿。

| 热点 | 原来 | 现在 |
| --- | --- | --- |
| 目录识别 | 每元素读 `innerText` | 先按 `children.length <= 1` 零成本过滤，再读 `textContent`；1804 节点实测 **40.3ms → 2.4ms** |
| iframe 列表 | 一轮里多次递归遍历 | 350ms 短缓存（`allDocs(force)` 可强刷） |
| 滚动容器探测 | 每次全文档 `getComputedStyle` | 2 秒缓存 |

## 播放器停在 0:00 与「假看完」（v0.9.12）

现场现象：浮窗显示「正在看视频 · 已看 2 个 · 进度 0 / 922 s」，页面中间的大播放按钮还在，工具一直不往下点。

两个根因：

1. **浏览器自动播放策略**。Chrome 只允许静音自动播放，脚本触发的有声 `play()` 会被拒绝；旧版 `v.play()` 的 rejected Promise 被 `.catch(()=>{})` 静默吞掉，于是 `waitFinish` 一直等到 20 分钟超时。
2. **「看完」判定过松**。原来 `waitFinish` 里「video 元素消失」直接 `return true`（SPA 换 video 时会短暂消失），平台把条目标成「已完成」也会在 3 秒后判定看完——所以会出现「已看 2 个」但一个都没真播。

修复：

- `ensurePlaying()` 在 `paused` 时先 `v.muted = true`，再点落在 video 矩形内的播放遮罩（`.vjs-big-play-button` / `[class*=big-play]` 等，排除暂停/下一集按钮与自己的浮窗），最后 `v.play()`；播放起来后尝试 `muted = false` 把声音还回来，若浏览器因此暂停，下一轮会自动重新静音续播。
- 引入 `everProgressed`（`currentTime > 0.5` 才算真播过）：`ended`、平台完成标记、播放器消失，**三者都必须在真播过之后才采信**；播放器消失后还要平台标记完成才算数，否则 20 轮后跳过。
- 一直没开始播放（`noStart`）会分阶段提示「已改为静音并尝试点播放按钮」「请手动点一下播放按钮」，并在 `maxNoStartSec`（默认 90 秒）后跳过，不再干等 20 分钟；读不到播放器（跨域 iframe）同样有兜底。
- 浮窗进度增加「（等待播放）」后缀，一眼能看出是卡在起播还是正常播放中。

测试：`tests/mock-course.html` 新增 `?needPlay=1`（模拟只有静音才允许自动播放 + 大播放按钮）与 `?noPlay=1`（点开即标已完成但一秒不播）；`tests/videobrush.e2e.mjs` 增至 11 个场景（J 能静音自启并真正播完 5 个、K 没播的不计入已看），11/11 通过；`tests/autorun.e2e.mjs` 11/11 回归通过。

## 「开始自动看视频」点了没反应（v0.9.13）

现象：点弹窗 ① 区的「开始」毫无变化，也没有任何提示。

三个叠加原因：

1. `refreshVBrush()` 里 `startBtn.disabled = !!(s && s.running)`——只要 storage 里残留上一轮的 `running:true`（上一轮卡在 0 秒、或页面刷新过），按钮就是禁用的。

3. `start()` 遇到 `st.running` 只 `note("已经在运行了")` 就返回，即使按钮能点也不会重启。

修复：

- **按钮永不禁用**：`running` 时文案改为「重新开始（会清掉本轮进度）」；`qvb_start` 带 `force:true`。
- `setVNotice()` 把启动/失败提示写进 ① 区 `#vbrushStatus`，并用 `vNoticeUntil` 保护，不被 1.2 秒的进度轮询覆盖；同时同步到 `#status`。

- 状态框显示 `chrome.runtime.getManifest().version`，一眼可确认扩展版本。
- **强制重启不抢点**：`loopRunning` 布尔守卫换成 `runGeneration` 代数，`tryClick` / `waitFinish` / 主循环全部校验 `gen === runGeneration`；旧循环自行退出，只有最新一代能写结束状态。页面刷新时的「自动停止」也加了 `!st.running` 保护，避免覆盖刚启动的新一轮。

## 「刷完了但平台没显示完成」（v0.9.17）

平台是否打勾由它自己的服务端决定，客户端能做的是保证「真播完 + 给足上报时间 + 明确告知结果」。

**根因 1（主因）：提前 1.5 秒判定播完。** `videoState()` 原来是 `dur - cur <= 1.5` 就算 `ended`。2 倍速下每秒采样，进度常直接落进这个窗口，于是视频还没真正结束就 `return true` → 1.2 秒后点开下一个，SPA 切页卸载播放器，平台的 `ended` 事件与最后一次心跳都没发出去，目录永远不打勾。改为只认 `v.ended` 或 `cur >= dur - 0.2`，并在 `waitFinish` 绑定一次 `ended` 事件监听作为证据（`ctx.endEvent`）；进度被播放器重置时也能凭事件判定播完。

**根因 2：播完立刻切页。** 平台完成上报常靠 10~30 秒一次的定时心跳，最后一段进度需要时间落地。新增 `confirmComplete()`：真正播完后停留 `cfg.confirmSec`（默认 12 秒，弹窗可配 0~120）等平台在目录里打 ✓，期间一检测到就立刻进下一个；窗口内保存状态降为每 1.4 秒一次。

**根因 3：2 倍速 vs 真实时长计时。** 部分平台按真实墙钟秒数累计，2x 只记一半时长。`markUnconfirmed()` 记录未确认条目并累计 `unconfirmedStreak`；连续 2 个没打勾且 `cfg.autoSlowdown` 为真时自动 `cfg.speed = 1` + `rateLocked`，`ensurePlaying()` 会把 `playbackRate` 强制拉回 1。

**可观测性**：`st.unconfirmed[]` 最多 30 条，浮窗与 popup 状态框显示「⚠ N 个平台未显示完成」，结束汇总列出前 3 个名字。文案明确写了「也可能只是打勾样式没认出来」，避免把工具识别失败误报成平台没记。工具不伪造心跳或学习时长。

**UI**：折叠区新增「播完等待平台确认」秒数输入（默认 12）与「连续 2 个没打勾时自动改成 1 倍速」勾选（默认开），都通过 `launchVBrush()` 下发。

测试：`tests/mock-course.html` 加 `?nearTail=1`（在距结尾 1.5 秒处停 2 秒，旧逻辑会提前跳走）、`?lateCheck=N`（ended 后 N 秒才打勾）、`?noCheck=1`（播完但永不打勾）；`tests/videobrush.e2e.mjs` 增至 20 场景：S 断言 5 个视频都真的播完才跳、T 断言延迟打勾在确认窗口内等到且 `unconfirmed` 为空、U 断言不打勾会记录清单并自动降 1x。20/20 通过；`tests/autorun.e2e.mjs` 11/11 通过。
